## 2. 需求审核：发现四个必须解决的问题

### 问题 A：58 条被契约或测试引用，翻译会破坏断言

`METRIC_META` 的 13 个指标名里，**4 个被契约硬引用**：

| 指标名 | 契约 | 测试 | 文档 |
|---|---|---|---|
| 社会化度 | ✅ | ✅ | ✅ |
| 可及丰裕度 | ✅ | — | — |
| 技术渗透度 | ✅ | ✅ | ✅ |
| 转型冲击 | ✅ | — | — |
| 生产力 | — | ✅ | ✅ |
| 发展水平 D / 劳动替代率 / 劳动份额 / 不平等 / 自由实现度 / 社会凝聚 / 崩解风险 / 封建化风险 | — | — | — |

**判断**：指标名是**模型语义**，与杠杆名同类。契约 §1 定义「社会化度」是 `socialization` 的中文名，
测试断言 `m.socialization` 的语义。翻译它们等于让契约与代码脱节。

**结论：指标名不翻，与引擎区同等对待。** 这会砍掉一批短串。

### 问题 B：72 条是拼接片段，逐条翻译必然破坏语法

样本：

```
", 引力: "        "发展水平 "      " 年跨过制度闸门。"
"」从 "           "% 调到 "        "）引力最高者为「"
"分岔点不是一个时刻，而是一个窗口。窗口内四条引力同时作用于社会，"
```

这些不是完整句子，是 `'...' + x + '...'` 拼接的一段。逐条丢进翻译表会得到
「逗号空格 Gravity colon space」这种垃圾。

**结论：拼接片段必须改为整句模板 + `{var}` 插值**，即 `'引力: {v}'` 而非
`', 引力: ' + v`。这是**代码重构**，不是纯文案替换——工作量比预想大。

### 问题 C：36 条极短串有歧义，脱离上下文无法翻译

```
否 / 是 / 默认 / 未知 / 路径 / 终点 / 窗口 / 载入 / 中位 / 剧本 / 含义
渗透 / 社会化 / 丰裕 / 替代率 / 不等 / 自由 / 租金 / 情景 / 结局 / 一致性
```

`否`/`是` 是布尔值；`路径` 在「路径对照」与「文件路径」里含义不同；
`窗口` 在「分岔窗口」与「UI 窗口」里不同。

**结论**：这些必须**逐条看上下文**再定英文，不能批量机翻。属人工密集项。

### 问题 D：41 条含数字或契约符号，需保留结构

```
"闸门 0.68"          "安全 <0.45"        "§9.1 崩解系数偏高"
"2024 起点固定"      "阶段 0 不可达"      "±10% 扰动对终点的影响"
```

数字与 § 符号必须原样保留，只翻中文部分。

## 4. 待用户确认的三个决策点

1. **指标名是否翻译？** 我建议不翻（与引擎语义同待遇），但这意味着英文用户会看到
   `发展水平 D` / `社会化度` 这样的中文标签混在英文界面里。
   替代方案：翻译指标名，同时改测试断言为查 `socialization` 字段而非中文名（改动更大）。

2. **72 条拼接片段是否值得重构？** 重构会动视图层代码（不改引擎），
   有引入 bug 的风险，收益是英文句子语法正确。若不重构，英文界面会出现
   「, Gravity: 」这类碎片。我建议重构。

3. **B3 的 12 条长文（含马克思引文）如何处理？** 引文有权威英译（「the free development
   of each is the condition for the free development of all」），应使用通行译本而非自译。
   其余长文是模型说明，需人工润色。
